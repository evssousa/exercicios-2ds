# 📘 Aula 9: Validação com Usuário – Testes e Prototipagem

## 🎯 Objetivos da aula

- Compreender a importância de **validar uma solução com usuários reais**.
- Entender o que é um **protótipo**.
- Diferenciar protótipo de produto final.
- Aprender a realizar testes simples de uma solução.
- Compreender como o feedback do usuário pode modificar um produto.
- Relacionar validação com o desenvolvimento do produto criado no **Projeto 1**.

# 👤 Por que validar com o usuário?

Uma equipe pode acreditar que criou uma ótima solução e, mesmo assim, descobrir que os usuários **não conseguem utilizá-la ou não precisam dela**.

Por isso, antes de investir muito tempo no desenvolvimento, é importante testar.

Imagine uma equipe que desenvolveu um sistema durante dois meses.

Depois do lançamento, percebe que:

> "Os usuários não entenderam como utilizar."
> 

O problema poderia ter sido descoberto em poucos minutos através de um teste simples.

Por isso:

> **Não devemos apenas perguntar se uma ideia é boa. Devemos observar as pessoas tentando utilizá-la.**
> 

# 🧪 O que é validação?

**Validação** é o processo de verificar se uma solução realmente atende a uma necessidade ou resolve um problema.

Podemos pensar:

```
Problema
   ↓
Solução
   ↓
Teste com usuário
   ↓
Feedback
   ↓
Aprendizado
```

A validação ajuda a equipe a descobrir se está caminhando na direção correta.

# 🧩 O que é um protótipo?

Um **protótipo** é uma representação de uma solução que permite testar uma ideia antes de construir o produto completo.

Ele pode ser:

- desenho de uma tela;
- sequência de telas;
- modelo de papel;
- apresentação;
- formulário;
- fluxo de atendimento;
- modelo físico;
- versão simples de um sistema.

📌 O protótipo não precisa estar funcionando completamente.

Ele precisa ser suficiente para **permitir que uma ideia seja testada**.

# 📱 Exemplo de protótipo

Imagine que uma equipe queira criar um aplicativo para organizar tarefas escolares.

Antes de desenvolver o aplicativo completo, pode criar três telas:

```
┌─────────────────────┐
│   MINHAS TAREFAS    │
├─────────────────────┤
│ Matemática          │
│ Entrega: 20/09      │
│                     │
│ Português           │
│ Entrega: 22/09      │
│                     │
│ [+ Nova tarefa]     │
└─────────────────────┘
```

O aluno pode observar a tela e tentar explicar como adicionaria uma tarefa.

Se ele não conseguir, a equipe encontrou um problema **antes de desenvolver o aplicativo**.

# 📝 Protótipo não precisa de computador

Como estamos trabalhando sem depender do laboratório, os protótipos podem ser criados utilizando:

### ✏️ Papel

Desenhar as telas ou etapas da solução.

### 📱 Tablet

Quando disponível, utilizar ferramentas de desenho, apresentação ou edição.

### 🗣️ Simulação

Uma pessoa pode representar o sistema e outra pode representar o usuário.

📌 O objetivo é testar a **experiência**, não criar um produto perfeito.

# 👀 Como realizar um teste com usuário?

Um teste simples pode seguir cinco etapas:

```
1. Escolher o usuário
        ↓
2. Apresentar uma tarefa
        ↓
3. Observar
        ↓
4. Fazer perguntas
        ↓
5. Registrar aprendizados
```

## 📌 Exemplo

A equipe apresenta o protótipo de um sistema escolar.

Em vez de explicar tudo, pede:

> "Imagine que você precisa encontrar uma tarefa de Matemática. Mostre como faria."
> 

Agora a equipe observa.

O usuário:

- encontrou facilmente?
- ficou perdido?
- clicou no lugar errado?
- perguntou alguma coisa?

Essas informações são muito mais úteis do que simplesmente perguntar:

> "Você gostou?"
> 

# 🗣️ Perguntas úteis durante a validação

Depois do teste, podemos perguntar:

- O que foi mais fácil?
- O que foi mais difícil?
- O que ficou confuso?
- Você utilizaria essa solução?
- O que mudaria?
- O que está faltando?

# ⚠️ Não tente defender sua ideia

Um erro comum é o criador ficar tentando explicar o protótipo:

> "Não, você deveria clicar aqui..."
> 

Isso pode esconder um problema de usabilidade.

Se o usuário não consegue descobrir sozinho, **isso é uma informação importante para a equipe**.

O objetivo do teste não é provar que a equipe está certa.

É descobrir:

> **O que precisa ser melhorado?**
> 

# 🔄 O feedback modifica o produto

Imagine:

### Antes do teste

A equipe criou:

```
10 etapas para realizar uma tarefa.
```

Durante o teste, percebeu que os usuários estavam abandonando na etapa 5.

A equipe pode então:

```
Teste
 ↓
Problema identificado
 ↓
Simplificação
 ↓
Novo teste
```

Esse é um exemplo de **melhoria contínua do produto**.

# 📘 Aula 6: Como Participar de Sprints e Plannings

# 🎯 Objetivos da aula

- Entender o que é uma **Sprint**.
- Compreender como o trabalho é organizado durante uma Sprint.
- Entender o papel da **Planning**.
- Aprender como contribuir para o planejamento de uma equipe.
- Desenvolver uma postura mais ativa durante o planejamento.

# 🔄 O que é uma Sprint?

Uma **Sprint** é um período definido no qual a equipe trabalha para alcançar um determinado objetivo e entregar uma parte do produto.

Em vez de tentar fazer tudo de uma vez, a equipe trabalha em **ciclos menores**.

Exemplo:

```
SPRINT 1
Planejamento
     ↓
Execução
     ↓
Entrega

SPRINT 2
Planejamento
     ↓
Execução
     ↓
Entrega
```

A duração da Sprint depende da equipe e da organização. Em muitos times, utiliza-se um período de uma ou duas semanas.

# 🎯 O que é o objetivo da Sprint?

A equipe não deve simplesmente pensar:

> "Vamos fazer 15 tarefas."
> 

É mais importante entender:

> **Qual resultado queremos alcançar ao final desta Sprint?**
> 

Exemplo:

### Objetivo

> Melhorar o processo de cadastro de novos usuários.
> 

Para alcançar esse objetivo, algumas tarefas podem ser:

- simplificar o formulário;
- corrigir erros;
- melhorar mensagens;
- testar o cadastro.

# 📋 O que acontece durante uma Planning?

Na Planning, a equipe analisa o trabalho disponível e decide o que será realizado.

Um processo simplificado seria:

```
Tarefas disponíveis
        ↓
Prioridades
        ↓
Capacidade da equipe
        ↓
Escolha das tarefas
        ↓
Objetivo da Sprint
```

# ⭐ Prioridade

Nem todas as tarefas possuem a mesma importância.

Imagine:

```
Tarefa A → Corrigir erro que impede cadastro
Tarefa B → Alterar uma cor
Tarefa C → Criar nova funcionalidade
Tarefa D → Corrigir pequeno detalhe visual
```

Se o erro impede os usuários de realizar o cadastro, provavelmente possui prioridade maior.

A equipe precisa discutir:

> **Qual tarefa gera mais valor ou reduz maior risco?**
> 

# 👥 A Planning não é responsabilidade de uma única pessoa

Uma boa Planning envolve participação da equipe.

O programador, por exemplo, pode contribuir dizendo:

> "Essa tarefa parece simples, mas existe uma dependência técnica que precisamos considerar."
> 

Ou:

> "Podemos fazer essa funcionalidade, mas precisamos dividir em duas partes para conseguir entregar com segurança."
> 

Essa participação ajuda a evitar planejamentos irreais.

# 🧠 Não prometa o que não consegue entregar

Um erro comum é aceitar tarefas demais apenas para demonstrar produtividade.

Imagine que uma equipe normalmente consegue realizar 10 tarefas em uma Sprint.

Durante o planejamento, alguém decide colocar 25.

Provavelmente teremos:

- tarefas incompletas;
- atrasos;
- pressão;
- queda de qualidade.

Por isso:

> **Planejamento precisa considerar a capacidade real da equipe.**
> 

# 🛑 O que fazer quando uma tarefa é maior do que parecia?

Uma tarefa pode parecer simples no início e revelar vários problemas durante a execução.

Nesse caso, a equipe pode:

- dividir a tarefa;
- renegociar o escopo;
- informar o problema;
- reavaliar prioridades.

O importante é **comunicar cedo**.

# 👨‍💻 Como o programador deve participar?

Durante uma Planning, o programador não precisa apenas ouvir.

Ele pode:

### Questionar

> "Essa regra está definida?"
> 

### Alertar

> "Essa solução pode gerar um problema técnico."
> 

### Sugerir

> "Existe uma alternativa mais simples."
> 

### Estimar

> "Essa tarefa exige mais trabalho porque depende de outra parte do sistema."
> 

### Negociar

> "Podemos entregar a parte principal nesta Sprint e deixar essa melhoria para a próxima."
> 

# ⚠️ Participar não significa falar o tempo todo

Uma boa participação também significa:

- ouvir;
- prestar atenção;
- fazer perguntas relevantes;
- respeitar opiniões;
- comunicar riscos;
- contribuir quando tiver informação importante.

Uma equipe eficiente não precisa que todos falem o tempo inteiro.

Precisa que **as informações importantes apareçam no momento certo**.

# 📌 Exemplo de uma Planning

Imagine uma equipe desenvolvendo uma plataforma de cursos.

O Product Owner apresenta:

> "Precisamos permitir que os alunos recuperem a senha."
> 

O programador pergunta:

> "Já temos o envio de e-mail funcionando?"
> 

A resposta é:

> "Ainda não."
> 

O programador explica:

> "Então precisamos considerar essa dependência antes de assumir que conseguimos entregar toda a funcionalidade."
> 

A equipe então reorganiza o planejamento.

📌 Essa é uma participação profissional.

Fim da aula!

# 📝 Atividade Rápida

Uma equipe possui estas tarefas:

- **A:** corrigir um erro que impede usuários de fazer login;
- **B:** alterar a cor de um botão;
- **C:** criar recuperação de senha;
- **D:** criar uma nova animação para a página inicial;
- **E:** corrigir um erro que causa perda de dados.

A equipe consegue realizar apenas **três tarefas** nesta Sprint.

### Perguntas

1. Quais três tarefas você escolheria?
2. Por que elas devem ter prioridade?
3. Qual seria um possível objetivo para essa Sprint?

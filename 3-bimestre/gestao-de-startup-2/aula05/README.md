# 📘 Aula 5: Reuniões Ágeis – Daily, Planning, Review e Retrospectiva

# 🎯 Objetivos da aula

- Entender o propósito das principais reuniões ágeis.
- Conhecer **Daily, Planning, Review e Retrospectiva**.
- Diferenciar o objetivo de cada reunião.
- Compreender como participar de reuniões de forma objetiva.
- Evitar reuniões longas e sem propósito.

# 🔄 Por que existem reuniões ágeis?

Em uma equipe de produto, várias pessoas trabalham em diferentes partes do mesmo produto.

Sem comunicação, podem surgir problemas:

- duas pessoas fazendo a mesma tarefa;
- uma pessoa esperando outra;
- problemas não comunicados;
- prioridades diferentes;
- decisões que não chegam a todos.

As reuniões ágeis existem para **alinhar a equipe e facilitar o trabalho**.

Mas existe uma ideia importante:

> **Reunião ágil não deve existir apenas porque "temos uma reunião". Ela precisa ter um objetivo.**
> 

# ☀️ Daily

A **Daily** é uma reunião curta utilizada para alinhar o trabalho da equipe.

Normalmente acontece diariamente e possui duração reduzida.

O objetivo não é resolver todos os problemas durante a reunião.

É principalmente:

- saber o que está acontecendo;
- identificar impedimentos;
- perceber se alguém precisa de ajuda;
- manter a equipe alinhada.

## 🗣️ O que normalmente é discutido?

Um formato bastante conhecido utiliza três perguntas:

### 1. O que fiz?

O profissional fala brevemente sobre o trabalho realizado.

### 2. O que vou fazer?

Explica qual será o próximo passo.

### 3. Existe algum impedimento?

Informa algo que esteja dificultando o trabalho.

📌 Exemplo:

> "Ontem terminei a tela de cadastro. Hoje vou trabalhar na validação dos dados. Estou com dificuldade para entender uma regra do sistema e preciso conversar com o responsável pelo produto."
> 

Isso é muito mais útil do que:

> "Está tudo tranquilo."
> 

# 📋 Planning

A **Planning** acontece para planejar o trabalho que será realizado durante uma Sprint.

A equipe decide:

- o que será feito;
- quais tarefas são prioritárias;
- quanto trabalho é possível realizar;
- quem participará das atividades.

## 🎯 Exemplo

Imagine que a equipe tenha estas tarefas:

```
[ ] Corrigir erro no cadastro
[ ] Criar tela de perfil
[ ] Melhorar busca
[ ] Criar relatório
[ ] Alterar sistema de notificações
```

Durante o planejamento, a equipe analisa o que realmente deve entrar na próxima Sprint.

Não significa simplesmente colocar **todas as tarefas**.

É necessário avaliar:

> **O que é mais importante e o que conseguimos realizar?**
> 

# 👀 Review

A **Review** acontece ao final de uma Sprint.

A equipe apresenta o que foi desenvolvido.

Participam pessoas interessadas no produto, como:

- equipe de desenvolvimento;
- produto;
- clientes ou representantes dos usuários;
- outras partes interessadas.

O objetivo é verificar:

> **O que foi entregue e o que aprendemos com isso?**
> 

## 📌 Exemplo

A equipe trabalhou durante a Sprint para melhorar o cadastro.

Na Review, apresenta:

> "Nesta Sprint conseguimos reduzir o número de etapas do cadastro e adicionamos validações."
> 

Os participantes podem analisar o resultado e apresentar opiniões.

# 🔄 Retrospectiva

A **Retrospectiva** é diferente da Review.

Na Review, o foco principal está no **produto e no que foi entregue**.

Na Retrospectiva, o foco está na **forma como a equipe trabalhou**.

A equipe pode discutir:

### 👍 O que funcionou bem?

### ⚠️ O que não funcionou?

### 💡 O que podemos melhorar?

## 📌 Exemplo

A equipe percebe:

> "Tivemos dificuldade porque as tarefas não tinham informações suficientes."
> 

Então pode decidir:

> "Na próxima Sprint, vamos melhorar a descrição das tarefas antes de começar."
> 

# 🧠 Comparando as reuniões

| Reunião | Principal objetivo |
| --- | --- |
| **Daily** | Alinhar o trabalho |
| **Planning** | Planejar a Sprint |
| **Review** | Avaliar o que foi entregue |
| **Retrospectiva** | Melhorar a forma de trabalhar |

Uma maneira simples de lembrar:

```
PLANNING
O que vamos fazer?
        ↓
SPRINT
Vamos executar.
        ↓
DAILY
Como está o trabalho?
        ↓
REVIEW
O que entregamos?
        ↓
RETROSPECTIVA
Como podemos trabalhar melhor?
```

# ⚠️ O que NÃO fazer em uma reunião ágil?

Uma reunião perde eficiência quando:

- uma pessoa domina toda a conversa;
- assuntos que não interessam a todos ocupam muito tempo;
- problemas são discutidos sem as pessoas necessárias;
- ninguém registra decisões importantes;
- a reunião não possui objetivo claro.

📌 Se um problema precisa de uma discussão longa entre duas pessoas, pode ser melhor **continuar a conversa depois da reunião**.

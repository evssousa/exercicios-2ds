# 📘 Aula 10: MVP, MLP e MMP – Como Construir aos Poucos

## 🎯 Objetivos da aula

- Compreender as diferenças entre **MVP, MLP e MMP**.
- Entender diferentes formas de evoluir um produto.
- Aprender a definir o que deve ser desenvolvido primeiro.
- Compreender a importância de construir produtos em etapas.
- Relacionar essas estratégias ao produto desenvolvido pela equipe.

# 🚀 Por que não construir tudo de uma vez?

Imagine que uma equipe tenha uma ideia para um aplicativo.

Ela decide desenvolver:

- cadastro;
- login;
- pagamentos;
- notificações;
- chat;
- relatórios;
- inteligência artificial;
- sistema de pontos;
- integração com redes sociais.

Depois de meses de trabalho, finalmente lança.

Mas descobre:

> **Os usuários não queriam metade dessas funcionalidades.**
> 

A equipe gastou muito tempo antes de descobrir isso.

Por isso, produtos digitais costumam ser desenvolvidos **aos poucos**.

# 🧩 MVP – Minimum Viable Product

**MVP** significa:

> **Produto Mínimo Viável**
> 

É uma primeira versão que possui **o mínimo necessário para testar uma hipótese e gerar aprendizado real**.

A pergunta principal é:

> **Qual é a menor solução que podemos colocar nas mãos de usuários para aprender alguma coisa importante?**
> 

## 📌 Exemplo

Problema:

> Pessoas têm dificuldade para encontrar profissionais de serviços próximos.
> 

### Produto completo

Poderia ter:

- cadastro;
- mapa;
- avaliações;
- pagamento;
- chat;
- notificações;
- favoritos;
- histórico.

### MVP

Pode começar apenas com:

> **Uma lista de profissionais e seus contatos.**
> 

Já é possível testar:

> "As pessoas realmente querem encontrar profissionais dessa maneira?"
> 

# 😊 MLP – Minimum Lovable Product

**MLP** significa:

> **Produto Mínimo Adorável**
> 

A ideia é ir além de simplesmente funcionar.

O produto precisa entregar uma experiência que faça o usuário pensar:

> **"Isso é útil e eu gostaria de continuar usando."**
> 

## ⚖️ MVP x MLP

### MVP

Foco:

> **Funciona e permite aprender?**
> 

### MLP

Foco:

> **Além de funcionar, o usuário gosta da experiência?**
> 

## 📌 Exemplo

Imagine um aplicativo de tarefas.

### MVP

- adicionar tarefa;
- visualizar tarefa;
- marcar como concluída.

### MLP

Além disso:

- interface simples;
- organização agradável;
- mensagens claras;
- experiência fácil de entender.

O produto continua pequeno, mas passa a oferecer uma experiência melhor.

# 🚀 MMP – Minimum Marketable Product

**MMP** significa:

> **Produto Mínimo Comercializável**
> 

É uma versão suficientemente completa para ser **oferecida ao mercado**.

O objetivo é conseguir colocar o produto nas mãos de clientes de forma comercialmente viável.

## 📊 Comparando

| Conceito | Principal preocupação |
| --- | --- |
| **MVP** | Aprender e validar |
| **MLP** | Criar uma experiência que o usuário valorize |
| **MMP** | Ter uma versão pronta para comercialização |

Uma forma simples de visualizar:

```
MVP
↓
Aprender

MLP
↓
Aprender + encantar

MMP
↓
Aprender + encantar + comercializar
```

📌 Na prática, esses conceitos podem ser utilizados de maneiras diferentes dependendo da empresa e do produto. Eles não são necessariamente etapas obrigatórias e rígidas.

# 🧠 Como decidir o que desenvolver primeiro?

A equipe deve perguntar:

### 1. Qual problema estamos tentando resolver?

### 2. Qual funcionalidade é realmente necessária?

### 3. O que podemos deixar para depois?

### 4. O que precisamos testar primeiro?

# 📌 Exemplo completo

Imagine uma plataforma para ajudar estudantes a encontrar materiais de estudo.

## 💡 Ideia completa

```
Login
Perfil
Busca
Recomendação
Chat
Avaliações
Ranking
Notificações
Gamificação
```

### MVP

```
Busca
+
Lista de materiais
```

### MLP

```
Busca
+
Lista de materiais
+
Interface simples
+
Experiência fácil
```

### MMP

```
Busca
+
Lista de materiais
+
Boa experiência
+
Cadastro
+
Forma de disponibilização
+
Modelo comercial
```

A equipe vai adicionando complexidade **somente quando houver necessidade e aprendizado que justifique isso**.

# ⚠️ O perigo de colocar funcionalidades demais

Esse problema é conhecido como **feature creep**.

A equipe começa com uma ideia simples:

> "Vamos criar uma plataforma de estudos."
> 

Depois:

> "Podemos adicionar chat."
> 

> "E ranking."
> 

> "E inteligência artificial."
> 

> "E gamificação."
> 

> "E uma rede social."
> 

O produto vai ficando cada vez maior.

📌 O problema é que a equipe pode perder o foco:

> **Qual problema estamos tentando resolver?**
> 

# 🎯 Construir aos poucos

Uma estratégia mais saudável é:

```
Problema
   ↓
Primeira solução
   ↓
Teste
   ↓
Aprendizado
   ↓
Melhoria
   ↓
Nova versão
```

Cada versão deve existir por um motivo.

# 📝 Atividade Rápida

Uma equipe criou uma plataforma para ajudar pequenos comerciantes a organizar pedidos.

Analise as três situações:

### Situação A

A equipe criou uma lista simples onde o comerciante consegue registrar e visualizar pedidos.

### Situação B

Além da lista de pedidos, a equipe melhorou a interface, facilitou o cadastro e tornou a utilização mais agradável.

### Situação C

A equipe possui uma versão estável, uma experiência adequada para os usuários e uma forma definida de oferecer o serviço comercialmente.

Identifique cada uma:

- MVP
- MLP
- MMP
